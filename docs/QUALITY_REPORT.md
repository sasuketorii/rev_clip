# 既存機能の品質検証 — 2026-09-16

## 1. 結論

**条件付きの候補です。公開Release・タグ・更新配信は実施していません。**
取得・保存・貼り付け待機・終了・履歴の同一性を修正しました。新機能やUI再設計はありません。隔離したRelease XCTestでは全271件が成功しましたが、通常Releaseによる実際の入力先への挿入、長時間の常駐性能、配布後の更新までを合格にしたものではありません。

## 2. 基準と対象

- 開始コミット: `878b42b45f21e1495d3c10c211406a8fe41abfbf`（公開v0.1.6 / build 39）。
- 候補: 未公開の **0.1.7 / build 40**。修正ブランチ: `quality/current-flow-20260916`。候補の確定SHA・バイナリSHA-256はローカル証拠の `candidate-manifest.json` に記録します。

- 比較: Release / arm64の同一テストフラグ、名前付きペーストボード、メモリ上の設定、隔離DB、使い捨て暗号鍵。通常起動のReleaseやDemoの測定と混同しません。
- 基準側には試験環境の隔離と再現テストだけを追加。製品の取得・保存処理は変更していません。

## 3. 直した問題

| 問題と根拠 | 修正 | 回帰確認 |
| --- | --- | --- |
| 内部貼り付けの約1秒間、後続の外部コピーB/Cまで取得されない。基準側の合成試験で再現 | 時間窓のフラグを廃止し、内部書き込み後のchangeCountだけを除外 | B/Cを順序どおり取得・処理 |
| 前の保存処理が次の取得を待たせる。250ms遅延注入で再現 | 取得と保存の直列キューを分離 | 次の取得待ちを比較、飽和時の順序検証 |
| 貼り付け待機中のクリップボード変更・対象変更の検査不足（ソースと合成状態遷移） | 操作世代・対象・前面・changeCountを再検証。取得できたAX入力欄が変わった場合もキャンセル | 別アプリ、終了、固定期限後の遅延コールバック、AX中の期限超過、次の操作、書き込み失敗 |
| 終了時に保存キューの完了を待たない（ソース） | 新規取得を止めて両キューをドレイン。5秒で完了しなければ終了を取り消す | 遅延完了、重複終了、タイムアウト、監視再開 |
| 同時刻の履歴の表示順と保持対象の不一致（合成DB） | 表示も `update_time DESC, id DESC` に統一 | 件数削除・再オープン後の一致 |
| 異なるデータ形式が同じハッシュ入力になる（合成構造） | フィールド名・有無・長さ・配列境界を含むv2同一性。旧ハッシュ一致は認証済み原本の全フィールド比較後にだけ再利用 | 旧行・旧ファイル保持、形式差の別保存、RTF/RTFD往復 |

旧ハッシュの再現は構造的な合成ケースであり、一般アプリが同じ不正RTFDを生成することを確認したものではありません。保存形式・暗号方式の移行や既存データの一括書き換えは行いません。

## 4. 正しさの結果

- Release XCTest: **271件成功、40.278秒**。実行中のソース変更なしをharness receiptで確認。
- Debug XCTest: **271件成功、39.275秒**。Releaseとは別実行。
- CLI／スキルインストーラ: **77件成功、6.030秒**。合成Unix socketと一時ホームのみ。その内数であるネイティブ37件を、署名済み候補の同梱CLIでも再実行し成功（11.209秒）。
- 10,000件の取得済み合成オブジェクトを250件ずつ処理し、順序・同一オブジェクト・待機カウンタ復帰を確認。10,000回のOSコピーやディスク保存の試験ではありません。
- 実際の隔離暗号化ファイル保存をINSERT前で止め、ドレイン→履歴消去後に行・ファイル・遅延通知が復活せず、テンプレートが残ることを確認。
- キューの目安は保存中を含む16件／100MiB。満杯なら取得済み原本を保持して待機します。設定上許可された大きい1件は単独で処理します。取得済み待機1件、暗号処理、画像の作業領域は別に存在するため、アプリの総メモリ100MiB上限ではありません。
- 全体試験の初回では、試験用オブジェクトの終了処理漏れと、ホスト言語を参照する期待値の不一致が発生。試験の隔離を修正した後に全体を再実行しました。初回失敗を成功として数えていません。

## 5. 同条件の性能比較

| 条件 | 基準 | 修正後 | 解釈 |
| --- | ---: | ---: | --- |
| 保存境界に250ms遅延を注入した次の取得待ち（各1回） | 261.374ms | 4.710ms | 直前の保存待ちによる遅延を分離。体感全体の倍率ではない |
| 軽い取得100回 P50 | 0.084ms | 0.092ms | 取得単体は高速化したとは言えない |
| 同 P95 | 0.189ms | 0.193ms | 同上 |
| 同 最大 | 0.456ms | 0.405ms | P99は報告しない |

実際の500ms監視タイマーと名前付きOSペーストボードで、各間隔6回ずつ書き込み、最後に600ms待ちました。保存境界はメモリ上の観測です。

| コピー間隔 | 生成数 | 基準: 観測／処理 | 修正後: 観測／処理 |
| --- | ---: | ---: | ---: |
| 1000ms | 6 | 6 / 6 | 6 / 6 |
| 500ms | 6 | 6 / 6 | 6 / 6 |
| 250ms | 6 | 3 / 3 | 3 / 3 |
| 100ms | 6 | 2 / 2 | 2 / 2 |
| 50ms | 6 | 1 / 1 | 1 / 1 |

観測前に上書きされたコピーは回収できません。少数試行・タイマーとの位相に依存する結果で、一般的な捕捉率ではありません。監視間隔の既定値は維持しました。メニュー体感P95、実際の挿入、通常Releaseの10分アイドルCPU／RSS、30分混合操作は**未測定**です。短時間のテスト所要時間から推定しません。

## 7. 安全性と限界

取得前の除外アプリ／秘匿型チェック、暗号認証、履歴非公開CLI、削除境界の既存回帰を含めています。ユーザーの一般クリップボード・設定・保存データ・Keychain項目の書き換えは行いません。外部へのバグ報告、スキルの実ホームへの配置、ネットワークプレビューの実送信は今回の試験対象ではありません。

AX入力欄を初回から取得できないアプリでは、従来の貼り付け機能を維持し、アプリ単位で検査します。同じ入力欄の維持は保証できません。既存のCGEvent配送経路を維持しており、検査とOSによる配送は原子的ではありません。550msは操作開始からの送信可否の期限であり、同期OS呼び出しを中断して戻す実行時間保証ではありません。暗号化のOS権限に対する限界は[SECURITY.md](../SECURITY.md)を参照してください。
