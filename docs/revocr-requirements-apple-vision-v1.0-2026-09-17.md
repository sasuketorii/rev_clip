## 0. 実装担当者への依頼

RevclipにRevOCRを統合してください。新しい独立アプリを作るのではなく、既存のコピー・履歴・設定・権限・終了・消去の仕組みに接続する入力機能として実装します。

設計案やTODOの提出だけで終わらず、権限内の実装、必要な回帰テスト、隔離した実機確認、通常Releaseの計測、配布候補の確認まで進めてください。公開・本番アプリの置換は別途明示された委任の範囲に限ります。

着手時は実際のHEAD・作業ブランチ・未コミット変更・既存の指示を確認します。参照SHAより新しい修正がある場合は新しいコードを優先し、旧コードへ戻しません。すでに実装済みの同等機能は再利用します。

本書の「必須」は機能・安全・互換性の受入条件です。「目標」は計測する性能・精度の目安であり、達成済みの事実ではありません。「初期仕様」は今回採用する設計上の既定動作です。変更が必要なら、理由と影響を記録し、対象範囲の拡大を伴う変更は承認対象にします。

優先順位は、①既存データと秘密情報を守る、②別のコピーを壊さず正しく結果を渡す、③素早い操作を妨げない、④非使用時の負荷を増やさない、⑤保守しやすくする、の順です。

## 1. 製品の目的と完成像

### 1.1 解決する課題

Web画像、画面共有、アプリ内の選択できない文字などを、手入力せずにコピーできるようにします。ユーザーがファイル保存・OCRアプリ起動・画像読み込み・結果の再コピーを往復する必要をなくします。

代表的な利用対象は、日本語・英語の文章、日英混在のUI、URL、メールアドレス、数字、短いコードや識別子です。認識した文字列を勝手に要約・翻訳・言い換えしません。

### 1.2 完成条件の考え方

「Apple Visionを呼んだら文字が返った」だけでは完成ではありません。次の連続した動作が成立していることを完成条件にします。

```text
ユーザーが起動
  → 必要な権限と現在の状態を確認
  → 選択対象の画面を一度だけ取得
  → AppKitで範囲を指定
  → 指定範囲だけをApple Visionへ渡す
  → 認識結果を必要最小限に整列
  → キャンセル・別コピー・消去との競合を確認
  → クリップボードへ一度だけ反映
  → 許可される場合だけ既存の保護された履歴へ登録
  → 画面画像と一時状態を解放
```

既存の⌘C、⌘⇧V、テンプレート、プレビュー、自動貼り付け、CLI、通常版／Demo版の動作は維持します。

### 1.3 今回しないこと

他のOCRエンジン、Rust導入、独自モデル、モデルダウンロード、クラウドOCR、生成AI補正、翻訳、要約、PDF一括処理、表のExcel化、手書き専用モード、QR読取、連続自動監視、OCR履歴専用DB、新しいMCP・公開CLIの画面読取コマンドは追加しません。

独自のOCR学習、汎用プラグイン機構、複数バックエンドの抽象化、アプリ全体のSwift移植やUI刷新も対象外です。Apple Vision内の設定調整は可能ですが、比較研究そのものを出荷の目的にしません。

## 2. 固定する技術構成

| 領域 | 今回の選定 | 実装上の方針 |
|---|---|---|
| 範囲選択 | AppKit | `NSPanel` / `NSWindow`と専用`NSView`。既存のmacOS操作体系に合わせる |
| 画面取得 | ScreenCaptureKit | `SCScreenshotManager.captureImage(contentFilter:configuration:)`系の単一画像取得を基準にする [A1][A2] |
| 認識 | Apple Vision | macOS 14との互換性を保つ`VNRecognizeTextRequest` + `VNImageRequestHandler`を初期実装の一本にする [A3] |
| 画像形式 | メモリ上の`CGImage` | PNG/JPEGへの書き出し・再読込を標準経路に置かない |
| 実装言語 | 新規部分はSwift、既存接続はObjective-C / Swift | 既存のブリッジを使い、言語を増やさない |
| 保存 | 既存の履歴保存サービス | SQLCipher / 認証付き暗号化 / Keychain等の既存方針を維持 [R5] |
| ホットキー | 既存`RCHotKeyService` | OCRの登録・解除・衝突処理を追加。別ライブラリを導入しない [R2] |
| 計測・テスト | 既存XCTest・既存スクリプト + 必要最小限の計測 | ソース・合成試験・実アプリ・配布物の証拠を分ける |

### 2.1 OSとAPIの扱い

最低対応OSは現行のmacOS 14.0を維持します。新しいmacOS専用の`SCScreenshotConfiguration`や新Swift Vision APIを、無条件に呼ぶ実装にしません。初期実装は互換性のあるAPI経路を一つにそろえます。

Appleの公開資料でAPIの存在・意味を確認し、実装時に採用XcodeのSDK宣言とavailabilityを照合してください。新しいSDKでコンパイルできることを、最低OSで動作する証拠にはしません。

`VNRequest.revision`は、特定の古い番号を全OSへ強制しません。初期値は使用環境の既定revisionを使い、実際の値・OS・SDKを検証記録へ残します。OS更新で結果が変わる可能性を前提に、代表コーパスを再実行します。[A9]

参照時のプロジェクトはSwift 6.0・Xcode 26.6という設定ですが、それを「将来も最新」とは扱いません。既存の安定したビルド構成を維持し、無関係な全依存更新を同時に行わないでください。[R1]

### 2.2 通常版・Demo版

同じソースと同じOCR機能を使います。Bundle ID、UserDefaults、データ領域、Keychain識別、ホットキー登録、更新フィードの違いは既存の配布メタデータで管理します。

通常版とDemo版が同じOSセッションで同時起動し、同じOCRショートカットを要求した場合は、既存の登録失敗処理で扱います。一方が他方の登録を勝手に解除したり、接続先を変更したりしません。

## 3. 初期仕様の決定表

以下は今回の実装用の初期仕様です。性能数値は第15章で別に扱います。

| 項目 | 初期仕様 |
|---|---|
| OCR起動 | ⌘⇧2。既存のショートカット設定で変更・解除できる |
| メニューの入口 | 「画面の文字をコピー…」。ホットキーが使えなくても起動可能 |
| 機能の初期状態 | コマンドとホットキーは有効。画面収録許可は初回の明示的な利用時だけ要求 |
| 選択方法 | 起動時にポインタがあるディスプレイを一枚取得し、その静止画上で選択 |
| マルチディスプレイ | 内蔵・外部をそれぞれ利用可能。一度の矩形が複数画面をまたぐ操作は今回対象外 |
| 認識品質 | `.accurate`。`.fast`は必要な調整試験に限り、既定では使わない |
| 言語 | 「自動」を既定。日本語・英語混在を優先的に検証。手動指定は実行環境が返す対応言語から選ぶ |
| 言語補正 | 既定OFF（原文優先）。自然文向けにONへ変更できる小さな設定を設ける |
| 改行 | 認識した行を原則維持し、行区切りをLFへ統一する |
| 自動貼り付け | OCR完了時には実施しない。コピー後はユーザーが⌘Vする |
| 履歴保存 | OCR結果の履歴保存設定は既定ON。ただし共通の保存可否判定に従う |
| 元画像 | 一時的なメモリ上のみ。画面画像・切り抜き画像・専用サムネイルは保存しない |
| 成功通知 | 非アクティブな短い通知。「コピーしました」。本文は表示しない |
| 無検出・選択取消 | コピーも履歴追加もしない |
| 処理中の別コピー | OCR結果を自動反映せず破棄。最新のクリップボードを優先する |
| 処理の並列度 | 同時OCRは1件。連打で認識処理を積み増さない |
| 通信 | RevOCRの画像取得・文字認識・結果確定に、アプリが外部通信を追加しない |

言語補正OFFは、一般の文章で常に精度が高いという意味ではありません。Appleは、OFFで未補正の結果を返すことと精度・性能の交換条件を説明しています。URLやコードの改変を避けるための既定値として採用し、自然文のON/OFFも同じ画像で確認します。[A6]

## 4. 利用フローとUI

### 4.1 初回利用

1. ユーザーが⌘⇧2またはメニューを実行する。
2. 設定無効・緊急消去中・終了処理中・保護された保存領域が使用不能等の状態を確認する。
3. 画面収録が未許可なら、機能の目的とデータの扱いを説明してOSの許可導線へ進む。
4. 許可設定から戻った後は状態を再取得する。古い画面選択要求を勝手に再開せず、もう一度操作するよう案内する。
5. OSがアプリ再起動を求める場合はその案内を尊重し、自動的に権限を変更しない。

説明文案：

> 画面上の文字をコピーするために、画面収録の許可が必要です。選択用に対象画面の静止画を一時取得し、囲んだ範囲だけをMac上で文字認識します。画像は保存・送信しません。認識した文字は、設定に従ってRevclipの履歴へ保存されます。

「選択した範囲以外は一切取得しない」とは表示しません。本仕様は、選択用に対象画面一枚を先にメモリへ取得する方式です。

### 4.2 通常利用

起動直前の前面アプリ、対象ディスプレイ、クリップボードの`changeCount`、監視の生存期間、OCR操作IDを記録します。クリップボード本文は読みません。

コマンドを実行した既存メニューが閉じてから画面を取得します。対象画面取得中は、選択枠や進捗表示をキャプチャへ混入させません。フレーム取得後にだけ、そのフレームを背景とする選択UIを表示します。

矩形をドラッグしてマウスを離すと選択確定です。表示していた同じフレームから範囲を切り出し、認識へ進みます。確定後のライブ画面を撮り直して、選んだ内容と認識内容を変えません。

### 4.3 選択UI

背景は取得した静止画。選択外を軽く暗くし、選択枠・十字カーソル・短い操作案内を表示します。既存ブランドや設定画面を再設計せず、macOSの道具として自然な最小UIにします。

ドラッグ方向は四方向すべてを扱います。矩形は正規化し、対象画面へ制限します。小さすぎる矩形は認識せず、同じ選択セッションで選び直せるようにします。右クリック、Esc、OCRホットキーの再押下で取消できます。

対象画面以外へまたがるドラッグは境界で制限し、「別の画面は、ポインタを移してもう一度起動してください」と分かる案内にします。倍率の異なる画面を一枚に合成する機能は作りません。

選択中にディスプレイ構成・解像度・回転・Space・ログインセッションが変わり、同じ座標の意味が維持できなくなった場合は取消します。別画面へ黙って切り替えません。

### 4.4 認識中とフォーカス

範囲確定後は選択UIを閉じ、不要な全画面画像を解放し、ユーザーを元の作業へ戻します。認識が短時間で終わる場合、進捗UIを点滅させません。300msを超えた場合だけ、非アクティブな小さい「文字を認識中…」表示と取消ボタンを出す初期仕様とします。

認識中にOCRホットキーを再押下した場合は、現在の処理を取消します。その次の押下で新しい操作を開始します。選択UIを閉じた後、別アプリへ入力されるEscを奪うためのグローバルキーロガーや新しい入力監視権限は追加しません。Esc取消の保証範囲はRevOCRの選択UI等がキー入力を受ける間です。

元アプリへのフォーカス復帰は、RevOCRが一時的に奪った場合にだけ行います。ユーザーが別アプリを選んだ後に、以前のアプリを強制的に前面へ戻しません。認識完了時もフォーカスを奪いません。

### 4.5 アクセシビリティと表示

設定項目、起動コマンド、取消ボタン、状態通知に読み上げ名を付けます。ライト／ダーク、コントラスト、透明度を下げる設定に対応し、色だけで状態を伝えません。成功通知は本文を読み上げません。

初期の範囲指定はポインタ操作が主経路です。スクリーン上の任意矩形の完全なキーボード指定や視覚に依存しない領域選択を実装していない場合、完全なアクセシビリティ対応を宣伝しません。既存のRevclipの読み上げ・キーボード操作は後退させません。

## 5. 画面取得・座標・画素の要件

### 5.1 単一フレームの取得

`SCShareableContent`で得た対象と`SCContentFilter`、`SCStreamConfiguration`を使い、`SCScreenshotManager`から`CGImage`を受け取ります。スクリーンショット取得のために常時`SCStream`を動かしません。Appleは単発取得用の非同期APIを提供しています。[A1][A2]

AppKitの`NSScreen`とScreenCaptureKitの`SCDisplay`はディスプレイIDで対応させます。配列の位置や画面名だけで対応を決めません。ミラーリングや外部画面着脱も検証します。

`showsCursor`はOFF。OCR用の画面にカーソルや自前の枠を焼き込みません。既存のRevclipウィンドウ全体を勝手に隠したり、他アプリの表示状態を変更したりしません。

### 5.2 解像度・色

取得サイズを明示し、APIの既定の低い出力サイズに依存しません。表示倍率と実フレームのピクセル数を照合し、UIの小さい文字が不要な縮小を受けないようにします。

OCR入力は向きの正しいSDR画像を基準とし、HDRや広色域の取得結果は文字のコントラストを壊さない方法で処理します。透明画像を扱う場合、黒地への予期しない合成等を防ぎます。Visionは入力のalphaを捨てるため、alphaに意味を持たせて認識を制御しません。[A9]

初期段階で二値化、超解像、複数画像の投票を常時実行しません。等倍の入力で実際の失敗が確認され、限られた変換が有効な場合のみ、比較結果付きで採用します。認識結果を複数回自動コピーすることは不可です。

### 5.3 座標変換

次を明確に区別します。

| 座標 | 単位・用途 |
|---|---|
| AppKit画面座標 | グローバルなポイント。画面ごとに負の原点もある |
| 選択ビュー座標 | 対象画面内のポイント。flippedの有無を固定する |
| フレーム画像座標 | 実際のピクセル。幅・高さは取得結果から確認 |
| Vision座標 | 正規化座標。採用APIの原点と向きに従う [A11] |

選択ビューを左上原点に統一した場合、選択矩形の最小辺にはfloor、最大辺にはceilを使って外側へ丸め、画像境界にclampする設計を基準とします。右下を独立に丸めてから幅・高さを計算し、ゼロ・負値・非有限値を拒否します。

単一画面でビュー全体がフレームに対応する場合の概念式：

```text
sx = framePixelWidth  / selectionViewWidthInPoints
sy = framePixelHeight / selectionViewHeightInPoints
x0 = floor(selectionMinX * sx)
y0 = floor(selectionMinY * sy)
x1 = ceil(selectionMaxX * sx)
y1 = ceil(selectionMaxY * sy)
```

これは左上原点へ正規化した後の式です。AppKitグローバル座標を直接入れません。`CGImage`の切り抜きや描画に必要な反転は、そのAPI境界で一度だけ行います。`backingScaleFactor`を全画面へ一律に掛ける実装にしません。

Retina 2x、非Retina、スケーリング表示、左・上にある外部画面、回転画面、画面四隅、1px境界を、合成格子画像と実画面で確認してください。

### 5.4 入力の上限（初期仕様）

| 対象 | 初期値 | 超過時 |
|---|---:|---|
| 取得フレーム | 32,000,000ピクセル | 安全に拒否し、対応範囲を案内。黙って縮小しない |
| OCR対象の切り抜き | 16,000,000ピクセル | 範囲を狭める案内 |
| 最小切り抜き | 幅・高さとも8ピクセル | 同じセッションで再選択 |
| 認識結果 | UTF-8で1MiB以下 | コピー・保存せず、範囲を狭める案内 |
| 同時認識 | 1件 | 新しい処理を無制限に起動しない |

これらは安全のための設計値で、Visionの公式上限ではありません。対応させたい実機で不足する場合は、メモリ計測と併せて見直します。`width × height`、`bytesPerRow × height`、切り抜き計算はオーバーフローを検査します。

画像の切り抜きオブジェクトが元の全画面バッファを共有している場合、「切り抜いたから全画面は解放された」と扱いません。必要なら範囲内だけの独立したバッファへ一度描画し、全画面参照を落とします。この複製は不要なPNG往復とは異なり、機密画像の保持期間とメモリを減らすためのものです。

## 6. Apple Visionの認識仕様

### 6.1 APIと実行

初期実装は`VNRecognizeTextRequest`を使い、`VNImageRequestHandler(cgImage:orientation:options:)`で切り抜き画像を処理します。認識は専用の直列実行境界で行い、メインスレッドを同期的に占有しません。

`.accurate`を既定とします。これは速度保証ではなく、精度を優先するAPI設定です。`.fast`へ切り替えて性能目標を満たしたことにせず、変更する場合は精度と対応言語の差を確認します。[A3][A4]

同じrequestオブジェクトを並行利用しません。Visionの完了コールバックをメインスレッドと仮定せず、UI・クリップボード・状態変更へ戻る場所を明示します。[A10]

### 6.2 主要な設定

| 設定 | 初期仕様 |
|---|---|
| `recognitionLevel` | `.accurate` |
| `usesLanguageCorrection` | 原文優先のため`false`。設定ON時のみ`true` |
| `automaticallyDetectsLanguage` | 自動モードで`true`。手動モードでは指定言語を優先する構成を確認 |
| `recognitionLanguages` | APIの対応一覧と照合した言語IDのみ。全対応言語の一括投入はしない |
| `minimumTextHeight` | 小さい文字を設定だけで除外しない低い値を採用。まず0.0を検証し、採用SDKの許容範囲・精度・負荷を確認 [A19] |
| `customWords` | 初期は空。ユーザーの履歴・連絡先・秘密情報を自動収集しない |
| `revision` | 実行環境の既定を使用・記録。根拠なく最大番号・古い番号へ固定しない |
| 実行デバイス | 原則OSに任せる。CPU限定やNeural Engine使用を未検証で固定・宣伝しない |

言語補正を無効にした場合、`customWords`は無視されるというAppleの仕様があります。補正OFFのまま独自辞書が効いていると説明しません。[A7]

### 6.3 言語対応

`request.supportedRecognitionLanguages()`等の採用APIから、現在の設定とOSに対応する言語一覧を取得します。Deprecatedなクラスメソッドを新規の標準経路には使いません。認識レベルによって対応言語が異なる可能性があります。[A5]

自動モードでは、ユーザーの優先言語、日本語、英語を起点に、実際に対応する言語へ正規化して優先リストを作ります。初期は最大3言語を目安とし、BCP 47等の表記差を解決したうえで重複排除します。言語IDを推測して無効な文字列を渡しません。

手動設定は「日本語＋英語」と「対応一覧からの選択」を提供します。保存された言語が別OSで非対応になったら、設定を黙って英語へ書き換えず、非対応を示して選び直せる状態にします。

保証範囲は次のように分けます。

- 必須の受入対象：横書きの日本語、英語、日英混在。
- 追加対応：実行環境が返す言語。各言語の実画面サンプルを確認したものだけ「検証済み」と表示。
- 初期の非保証対象：日本語縦書き・ルビ・縦中横、複雑な多段組み、任意回転、手書き、数式、複雑なRTLレイアウト。

APIの一覧にあることと、RevOCRで特定の縦書きや読順を保証することは別です。「全言語対応」「全OSで同じ精度」とは表示しません。認識結果が返る非保証対象は利用できますが、追加の専用エンジンや複雑なレイアウト解析は今回導入しません。

### 6.4 結果の取り扱い

各観測の`topCandidates(1)`を基準とし、文字列・矩形・信頼度を処理中の結果に保持します。信頼度を、校正済みの正答確率として表示しません。低スコアの文字や行を黙って削除して、見かけの精度を上げません。

結果が空、または空白だけの場合は`noText`です。クリップボードに空文字をコピーしません。APIエラーと無検出は別の状態にします。

URL、メール、コード、金額、電話番号等について、`O/0`、`I/l/1`、全角・半角、ハイフン、引用符、末尾桁を独自推測で書き換えません。OCR自体の誤認識があり得ることは明示します。

## 7. 読み順・空白・出力文字列

出力はテキストのみです。OCR用画像、矩形、confidenceをクリップボードへ別形式で混ぜません。

標準対象である横書きの単一列について、上から下・同じ行では左から右へ安定した順序にします。Visionが返した配列の順序を無条件の読順保証とせず、実際の観測と矩形を確認します。

同一行の観測が分割されている場合は、高さ・縦方向の重なり・横の間隔から限定的にグループ化します。曖昧なepsilon比較だけでソート順が非推移的になる実装を避け、行グループを確定してから安定ソートします。

候補内の文字・空白は維持します。別観測を連結する空白は、明確な単語間隔がある場合にだけ補います。日本語へ機械的に空白を挿入したり、元候補の空白を一律削除したりしません。結合が曖昧なら別行として残す方を優先します。

行の区切りはLF。自動の段落結合、ハイフン除去、NFKC正規化、引用符の置換、改行の全削除、Markdown生成はしません。CRLF等の行終端の統一と、結果全体の先頭末尾に生じた空行の除去は可能です。

画素からは元のタブ文字とスペース数を常に特定できません。コードのインデントやタブのバイト単位の完全復元は保証しません。行順や記号をアプリ側の整形で壊さないことを必須とします。

多段組みや複雑な表を自然文として完全に再構成することは対象外です。精度評価では、文字誤りと読順誤り、整形による改変を別に記録します。

## 8. 既存Revclipへの統合

### 8.1 現在の境界と、今回追加する境界

参照時の`RCClipboardService`には、内部書き込みの世代登録、既存履歴の利用記録、現在のクリップ取得、取得・保存のドレイン、メニュー表示前の観測APIがあります。[R3]

OCR結果は新しい入力です。以下のどれかだけで済ませる実装にはしません。

- `captureCurrentClipboard`を呼び、後から一般クリップボードを読み直して履歴へ入れる。
- 内部世代として除外しただけで、OCR結果が履歴に入らなくなる。
- `recordHistoryUseWithDataHash:`で新規OCR結果の作成を代用する。
- 既存と別のDB・JSON・画像ファイルへ結果を保存する。

必要なのは、**アプリ内で生成したテキストを、出所と操作文脈付きで受理する小さい内部入口**です。以下は設計名であり、既存APIの存在を示すものではありません。

```text
commitRecognizedText(text, context, completion)
  context:
    operationID
    OCR generation
    monitoring/lifecycle generation
    clipboard changeCount at invocation
    invocation app metadata
    save-to-history intent
```

この入口は公開CLIやネットワークへ公開しません。OCR以外への汎用拡張のために大きなイベント基盤を作りません。

### 8.2 コピーの確定

メインスレッド上の短い確定処理で、次を確認します。

1. 最新の有効な操作ID・世代であり、すでに確定していない。
2. OCRが有効で、取消・タイムアウト・ロック・終了・消去の後ではない。
3. 開始時と現在で監視の生存期間が対応しており、停止→再開した古い要求ではない。
4. テキストが空ではなく、サイズ・文字列処理が完了している。
5. クリップボードの`changeCount`が記録時と一致している。
6. 現在の除外設定・保存方針を再確認している。

成功時に必要な書込データをすべて準備してから、一度の論理的な書き込みとしてテキストを反映します。その直後に、最終の`changeCount`を`recordInternalPasteboardChangeCount:`へ登録します。[R3]

アプリ内部で「同じ操作を一度だけ確定する」ことを守ります。ただし、OSのペーストボードとDBが一つのトランザクションになるわけではありません。他アプリの更新に対する原子的なcompare-and-swapを提供するAPIだと仮定しません。

書込直前と直後の状態を確認し、他アプリの新しいコピーに古い値を再適用しないでください。事前確認とOS書込間の微小な競合を完全に排除できない場合、その限界を記録します。

### 8.3 別コピーとの競合

操作開始後に一般クリップボードが変更された場合、OCR結果は自動コピーも履歴保存もしません。短く「別のコピーを優先しました」と通知し、その操作の文字・画像を破棄します。

同じ文字列への再コピーであっても、内容を読むのではなく世代変更として扱います。元の内容を守る名目で、開始時の一般クリップボード本文をメモリやファイルへ退避しません。

コピー先アプリへの自動入力は行わないため、認識後の前面アプリを貼り付け先として推測しません。認識中の単なるアプリ切り替えは、別コピー・ロック・明示的取消等がなければ、それだけを理由に結果を失わせる必要はありません。

### 8.4 履歴への受理

コピーに成功し、履歴保存が許可される場合だけ、**そのOCR結果の不変スナップショット**を、既存の取得受付順・保存順・ドレインに接続して渡します。後から一般クリップボードの本文を読み直しません。

履歴の形式は既存のテキストクリップです。現行の重複判定、再コピー時の並べ替え設定、容量、期限、暗号化を利用します。OCRだから保持上限や除外を無視する経路を追加しません。

既存クリップと内容が同じ場合の統合・並べ替えは、通常の新しいテキスト入力と同じ契約に従います。「必ず新しいDB行が一件増える」ではなく、「一回の受理が二重処理されない」を要件にします。

履歴保存の判定には、OCR保存設定、既存の保存対象形式、除外、収集状態、鍵・DBの使用可能性を含めます。`RCPrivacyService.shouldCaptureClipboardContents`はペーストボードを読んでよいかのAPIであり、画面取得や内部生成テキストの包括的な許可APIとは扱いません。[R4]

画面収録許可だけを理由に、利用者が拒否した履歴収集方針を迂回しません。初期仕様では履歴収集許可が拒否・不明なら履歴には保存せず、OS上書込可能で安全な状態に限ってコピーのみとします。OSの読取権限のために、不要な本文読み取りを発生させません。

### 8.5 コピーのみの場合

OCRの「履歴へ保存」がOFF、または保存ポリシーによる意図的な除外の場合、通常監視が同じ結果を取り直して保存しないようにします。内部世代の除外に加え、既存処理が除外する`org.nspasteboard.TransientType`等のメタデータを利用する方法を検証してください。[R5]

適用したマーカーとテキストを同じ論理書き込みへ含め、アプリ再起動後の再取得や通常版／Demo版の相互取得も確認します。これは他の全アプリの保存やOSの同期を禁止する仕組みではありません。出力したテキストはOSクリップボードに存在することを明示します。

### 8.6 部分成功と失敗

| 状態 | 扱い |
|---|---|
| 認識成功・コピー成功・履歴保存成功 | コピー成功を通知。必要なら内部結果で保存完了も記録 |
| 認識成功・コピー成功・意図的に履歴対象外 | コピー成功。保存しない設定は正常動作 |
| コピー成功・履歴保存失敗 | コピーを取り消さず「コピーしましたが、履歴に保存できませんでした」 |
| 認識成功・コピー失敗 | 履歴にも新規登録しない。書込失敗を通知 |
| 確定前の別コピー・取消・無検出 | 書込も履歴登録もしない |
| アプリ終了・プロセス障害がコピーと保存の間で発生 | 未保存の可能性を契約として扱う。再起動時にOS本文を勝手に読んで補完しない |

`clearContents`後のOS書込失敗では、元のクリップボードを維持できない場合があります。「すべての失敗で絶対に元の内容が残る」とは保証しません。書込前に可能な検証と準備を終え、失敗後にさらに古い値を復元して被害を広げないことを必須にします。

成功通知は保存完了の証明と混同しません。`copied`、`historyPending`、`historyStored`、`historySkipped`、`historyFailed`を区別できる結果にします。

## 9. 状態遷移・取消・終了・消去

### 9.1 状態の所有者

状態管理は一つのCoordinatorが所有します。UIはMainActor／メインスレッドで扱い、認識や保存の状態を複数のManagerへ分散して独自に進めません。

```text
idle
  → checkingPermission
  → capturing
  → selecting
  → recognizing
  → committing
  → completed
  → idle

各段階 → cancelled / failed → idle
コピー確定後の履歴処理は、既存の保存受付・ドレインで完了させる
```

全コールバックは操作IDと世代を持ち、古い操作の完了が新しいUI・新しいコピーを変更しないようにします。UIの取消と、フレームワーク内部の処理停止は別の状態として管理します。

### 9.2 取消のきっかけ

選択中のEsc・右クリック・再押下、認識中の取消ボタン・OCR再押下、機能OFF、権限失効、画面ロック、ユーザー切り替え、終了、履歴消去、緊急消去で、その時点で未確定の操作を無効化します。

選択中の画面構成変更は取消します。認識がすでに独立した切り抜き画像へ移った後は、単なる画面配置変更だけでデータを捨てる必要はありませんが、ロック・セッション変更では必ず取消します。

`VNRequest.cancel()`を必要に応じて呼びます。ただし、取消要求の直後にCPU処理やOS内部メモリが必ず消えるという保証はせず、結果反映を止める世代ガードを独立に維持します。[A8]

### 9.3 タイムアウトと同時実行

現行の運用値（2026-09-25改訂）は画面取得5秒、選択無操作120秒、範囲確定から認識完了は起動後の初回成功まで60秒、以降10秒です。許可ダイアログのユーザー操作時間は取得時間へ含めません。これらは遅延要求を残さないためのアプリ側期限で、OS呼出しを強制終了する保証ではありません。

期限切れではUIと確定権限を解除し、遅い結果を使いません。OS処理が戻らない間に同じワーカーへ要求を無制限に積まず、新しい開始は「前の処理を終了しています」と短く扱います。強制スレッド終了や、初期からの巨大な別プロセス基盤は導入しません。

### 9.4 履歴消去との順序

既存の消去・終了境界に、OCRの新規確定を止めるフックを加えます。具体的には、消去開始時点でOCR世代を無効化し、選択UI・認識結果を破棄します。

消去より前にコピー確定と履歴受付まで済んだものは、既存のドレインで処理してから消去します。消去後に遅れて完了したOCRが、新しい行・メニュー・クリップボードを復活させてはいけません。

参照時のPanic Eraseにはproducer停止・キュー排出・破壊操作の順序があります。OCRを追加しても、その書込禁止境界を迂回しません。[R6]

### 9.5 終了

未確定のOCRは取消します。すでに履歴受付済みのテキストは既存の有限ドレインへ含めます。画像を保持したまま終了を無限に待ちません。

AppKitの入れ子になったメニュー追跡・終了待ちを考慮します。main queueへ投げた返信が、同じmain queueから入った待ちループで実行できない設計を再発させないでください。既存のrun loopを考慮した終了修正を維持します。[R7][A12]

## 10. 権限・プライバシー・セキュリティ

### 10.1 権限を区別する

| 権限・状態 | RevOCRとの関係 |
|---|---|
| 画面収録 | 画面取得に必要。明示的な機能利用時にだけ案内・要求 |
| アクセシビリティ | OCR認識とコピーのためだけには新規必須にしない。既存の自動貼り付けの権限と分ける |
| クリップボード読取 | 世代確認・自分で生成した文字のコピーのために、既存本文の読取りを追加しない |
| カメラ・マイク | 使用しない |
| 入力監視・フルディスクアクセス | 新規要求しない |
| 通知権限 | コピー完了のためにOS通知権限を必須にしない。アプリ内の短い表示で足りる |

`CGPreflightScreenCaptureAccess` / `CGRequestScreenCaptureAccess`等の公開APIと実際のScreenCaptureKitのエラーを照合します。許可状態の事前確認が成功しても、本取得が必ず成功すると仮定しません。TCCの直接編集、無断リセット、許可UIの自動承認は行いません。[A13][A14]

### 10.2 取得元と機密情報

起動前の前面アプリが既存の除外設定に一致する場合は、画面を取得する前に開始を拒否する初期仕様とします。選択UIを出した後の前面アプリがRevclipへ変わったことを利用し、除外を迂回しません。

ただし、前面アプリの情報は、矩形内のすべての画素の所有者を証明しません。複数アプリのウィンドウが混在する画面について、除外設定だけで秘密情報を完全に保護できると宣伝しません。

画像には、通常コピーのconcealed等のマーカーがありません。パスワード・APIキー・顧客情報を確実に自動検出する機能を持つと扱いません。認識結果の保存設定と、必要な除外をユーザーに説明します。[R5]

### 10.3 保存と通信

画像・結果本文・ウィンドウタイトル・URL・ファイル名を、性能ログ、クラッシュ添付、解析サービスへ自動出力しません。Debugでも実ユーザーの内容をデフォルトで保存しません。

原画像・切り抜き・認識結果の一時保持は必要な時間だけです。OSや言語ランタイム内部のメモリを完全消去したという保証はしません。メモリから明示的な所有参照を解放することと、鑑識的な消去は別です。

OCR入力を外部へ送信するコードは追加しません。OCR完了時に、抽出されたURLのリンクプレビュー・ファビコン・ネットワークアクセスを自動で開始しません。

その後ユーザーが既存の履歴メニューを操作した場合のリンク取得は、既存機能・設定の範囲で別途扱います。「Revclip全体が一切通信しない」「クリップボードへ出した情報が他アプリへ渡らない」とは表現しません。

### 10.4 CLI・エージェント境界

今回、公開CLIへ`ocr-screen`、画面取得、OCR直近結果取得、OCR履歴読取等を追加しません。既存の履歴非公開方針を維持します。テスト用OCR呼び出しは、合成画像のテストターゲット・ローカル検証に閉じます。

エージェントがテストするからといって、ユーザーの一般クリップボードや普段の画面を無断で読んでよいわけではありません。検証は第16章の隔離条件を守ります。

## 11. 設定画面と表示文言

既存の設定ウィンドウの表現に合わせ、RevOCRに必要な小さい設定ページまたはセクションだけを追加します。

| 設定 | 初期値・仕様 |
|---|---|
| 画面の文字をコピー | 有効。無効化でホットキー解除・未確定処理取消 |
| ショートカット | ⌘⇧2。既存の登録・保存・エラー通知を再利用 |
| 認識言語 | 自動 / 日本語＋英語 / 実対応一覧から選択 |
| 文章の言語補正 | OFF。説明：「文章向けの補正を使用します。URLやコードの読み取り結果が変わる場合があります」 |
| 認識結果を履歴へ保存 | ON。ただし共通の保存ルールに従う |
| 画面収録の許可 | 現在の状態と設定への導線。権限の自動変更なし |

エンジン一覧・モデル選択・バックエンド選択・GPU設定・細かい認識閾値の管理画面は追加しません。

処理開始時に認識設定をスナップショット化します。言語や補正を後から変更しても、実行中requestの一部だけを差し替えません。一方、機能OFF・保存OFF・除外追加等の保護を強める変更は、確定時にも再確認して尊重します。

認識開始後に保存OFF→ONとなった場合、すでに開始した結果を遡って保存対象へ広げません。開始時の保存意思と確定時の許可の両方が成立した場合だけ保存します。

通知文案：

| 状態 | 文言 |
|---|---|
| 選択中 | 「文字を囲んでください。Escでキャンセル」 |
| 長めの認識 | 「文字を認識中…」 |
| コピー成功 | 「コピーしました」 |
| 無検出 | 「文字が見つかりませんでした。範囲を選び直してください」 |

## 12. 内部データと責務分割

以下は責務の提案です。既存の同等実装がある場合は統合し、名前だけのクラスを量産しません。

| 責務 | 提案名 | 主な所有物 |
|---|---|---|
| 操作・世代・状態 | `RCOCRCoordinator` | 操作ID、状態、取消、設定スナップショット、ライフサイクル文脈 |
| 単一画面取得 | `RCScreenCaptureService` | 対象display、取得要求、frameの結果 |
| 選択UI | `RCOCRSelectionController` / 専用View | 画面画像、選択矩形、ポインタ・取消、座標変換 |
| Vision認識 | `RCVisionTextRecognizer` | 直列実行、request、取消、観測結果 |
| 純粋な整列 | 小さい関数または`RCOCRTextFormatter` | 認識行の整列・出力テキスト生成 |
| 確定と履歴 | 既存`RCClipboardService`への限定追加 | 世代検査、ペーストボード書込、共通保存受付 |

Swift側から既存Objective-Cへ公開するのは、小さい`@objc`入口・DTO・結果だけにします。既存のbridging headerと生成インターフェイスを利用し、SwiftとObjective-Cに同じ状態管理を二重実装しません。

### 12.1 操作文脈

最低限、操作ID、OCR世代、監視生存期間、起動時刻、対象display ID、フレーム寸法、座標変換、起動前のアプリID、開始時changeCount、認識設定、履歴保存意思を保持します。

これらは原則メモリ上の処理文脈です。全部を履歴DBへ永続化する必要はありません。アプリIDは実際の画像所有者の証明ではなく、除外判定等の文脈です。

### 12.2 認識結果

最低限、出力テキスト、各観測のテキスト・矩形・信頼度、実際の言語設定・revision、認識時間、警告を持ちます。結果は以後書き換えない値として扱います。

結果本文はログへ出しません。ログのoperation IDはランダム値を使い、本文ハッシュを識別子として記録しません。

### 12.3 エラー分類

`disabled`、`permissionRequired`、`permissionDenied`、`excludedContext`、`displayUnavailable`、`captureFailed`、`invalidSelection`、`inputTooLarge`、`unsupportedLanguage`、`noText`、`recognitionFailed`、`timedOut`、`cancelled`、`superseded`、`clipboardChanged`、`clipboardWriteFailed`、`historyFailed`等を区別します。

名称は既存のエラー規約に合わせて構いません。重要なのは、取消・無検出・コピー競合をクラッシュと混同せず、正常終了か失敗かをUIとテストで判定できることです。

## 13. スレッド・メモリ・負荷

### 13.1 実行境界

AppKitの表示、現在の操作状態、クリップボードの確定はメイン。画像の独立化・色変換・Visionの同期実行は、メイン以外の明示的な実行境界で扱います。

`Task {}`を書いただけで重い処理がMainActorから離れたと判断しません。使用するSwiftの隔離・Sendable契約を確認します。警告を消すためだけの広い`@unchecked Sendable`や、同期待ちの追加は避けます。

認識の待機中も、通常のコピー監視、履歴メニュー、テンプレート編集、CLIが不要に停止しないようにします。Visionが使う内部並列度に加えて独自並列OCRを増やしません。

### 13.2 非使用時

OCR未使用時に、画面取得、周期的Vision呼出し、画像キャッシュ作成、結果ログ出力、追加の監視タイマーを動かしません。起動ごとの全画面列挙やダミー認識によるウォームアップも既定ではしません。

登録済みホットキーと小さい設定・状態だけで待機します。OSのVision内部キャッシュをアプリが強制解放できると仮定せず、アプリ所有の画像・結果・クロージャの寿命を管理します。

### 13.3 メモリ予算

初期のアプリ所有画像バッファ予算は合計256MiBを目安とします。上限ピクセル数だけでなく、実際のrow stride・フォーマット・表示側共有・切り抜き側の複製を数えます。

これはプロセス全体のRSS上限ではありません。Vision・WindowServer・フレームワーク内部の割当は別に計測します。OCR後にRSSが直ちに初期値へ戻ることだけを要求せず、反復ごとに増え続けないことを確認します。

メモリ圧迫や割当失敗では、新しいOCRを受理せず、画像参照を解放して既存Revclipを継続できる状態にします。画面画像を平文ファイルへ退避してRAM不足を回避しません。

## 15. 性能・精度の測定と目標

### 15.1 何を測るか

| 指標 | 開始 | 終了 |
|---|---|---|
| 選択開始まで | ホットキーハンドラ受理 | 静止画上の選択UIが実際に操作可能 |
| 範囲確定後の待ち | mouse-up | クリップボードの書込完了 |
| 認識処理のみ | Visionの実行開始 | request結果取得 |
| 履歴反映まで | OCR結果受理 | 保存契約の完了と履歴からの再利用確認 |
| 取消応答 | 取消入力 | UIを閉じ、確定権限を失ったことの確認 |
| 既存機能への影響 | 同じ通常操作系列 | OCR追加前後のメニュー・保存・CPU・メモリの差 |

人がドラッグしている時間と許可ダイアログを操作する時間は、別に記録します。最初の画面取得をドラッグ前に行うため、mouse-up後の数値だけで全体が速いとは説明しません。

### 15.2 初期の性能目標案

基準はM2・16GB級の通常Release、既存履歴30件、電源状態を固定した検証です。実機が違えば別系列として記録します。未達なら未達を明示し、勝手に機能・精度を削って達成扱いにしません。

| 条件 | 目標案 |
|---|---|
| 権限取得済み・暖機後の選択開始まで | P95 250ms以内 |
| 1280×720px以内・横書き20行以内の通常文字領域、範囲確定→コピー | P50 150ms以内 / P95 350ms以内 |
| 選択UIの取消 | 100ms以内を目安。OS処理終了は別測定 |
| 未使用・安定後のOCR追加分 | 持続的な追加画面取得・認識0回。追加CPU平均0.1ポイント以内を目安 |
| 未使用・安定後のメモリ増分 | 同条件のRSS差10MiB以内を目標。footprintも別掲 |
| 100回の取得・認識・取消を交えた反復 | アプリ所有の画像・結果・待機仕事が残留せず、反復ごとの増加傾向がない |
| 既存メニューのP95 | 実測ノイズを除き10%超の後退がないことを目安に原因を調べる |

初回のVision利用・OS内部準備・初回画面列挙は別測定にします。初回を隠して暖機後だけを製品性能として宣伝しません。実際の端末・OSで目標に届かない場合は、支配要因と既存機能への影響を説明し、出荷判断を分離します。

### 15.3 精度評価

まず40枚程度の代表画像で不具合を直し、その後、調整に使っていない120領域程度の検証集合を使います。これは作業量の目安で、統計的な十分性の保証ではありません。同じ画像から量産した類似切り抜きを独立サンプルとして水増ししません。

最低限、横書き日本語、英語、日英混在、ダークUI、色付き文字、小さい文字、URL・メール・数字、コード、画面端を含めます。別に縦書き・表・ルビ・低解像度を挑戦ケースとして分けます。

指標は以下です。

- CER：置換・削除・挿入の合計 / 正解文字数。Unicode単位と改行の扱いを固定する。
- URL・識別子・数値の完全一致率。合計100フィールド以上を目安にする。
- 文字領域の検出漏れ、読順の誤り、整形による改変を別々に集計する。
- 既定の補正OFFと自然文の補正ONを、同じ画像・同じ認識レベルで比較する。

通常の判読可能な日本語・英語の横書き集合では、初期目標をCER 1%以下、URL等の完全一致率98%以上と置きます。これはVisionの保証値ではなくRevOCRの評価目標です。低解像度等の挑戦集合を通常集合から黙って外したり、未達結果を隠したりしません。

厳密一致と、改行・Unicode正規化等をした一致は別に報告します。URLやコードの差を正規化で消してはいけません。「Apple Visionなので100%」や、比較していない競合より高精度という表示は禁止です。

### 15.4 記録する条件

ソースSHA、未コミット差分、version/build、署名、実行バイナリハッシュ、通常／Demo／テスト、最適化と計測フラグ、Mac、RAM、OS、SDK、Vision revision、言語、補正設定、画像寸法、表示倍率、試行数、中央値・P95・最大値を結び付けます。

軽い試験は100回程度を目安にし、少数試行ではP99を示しません。P99を出すためだけに不要な長時間試験を追加する必要はありません。

通常Releaseで10分アイドル、30分の混合操作を確認します。実施していない時間を推定で埋めません。既存テストホストや過去のDemo測定を新しい通常版の計測値として流用しません。

## 17. 実装順序と作業の止めどころ

### フェーズ1：現在の土台と最初の一往復

HEADと隔離を確認し、既存の関連テストを実行します。合成画像をVisionへ渡して返す最小実装と、小さい起動・画面取得・選択の動作を作ります。最初から全文書の再設計や大量のテスト作成で止まらないでください。

この段階で他エンジン比較・将来のモデル交換機構を作りません。

### フェーズ2：表示と取り込みの一貫性

単一画面の静止画選択、倍率・座標、メニュー起動、Esc・再押下・画面変更の取消を完成させます。起動直前の文脈を保持し、画面画像をファイルへ書きません。

### フェーズ3：結果確定と既存履歴への接続

新しい内部受付を実装し、別コピーとの競合、二重保存、保存OFF、部分成功、Clear/Panic/終了の境界を先に閉じます。ここが未完成のまま見た目の調整へ移りません。

### フェーズ4：精度・性能の最小調整

等倍の切り抜き、言語、補正、minimumTextHeight、単純な読順処理を代表画像で調整します。同じ条件の前後比較で効果がない最適化は残しません。

Apple Visionを選んだ今回の判断を、独断で別エンジン導入へ変更しません。達成困難な条件が残る場合は、再現画像の区分と計測結果を出し、非保証範囲または次回判断として切り分けます。

### フェーズ5：実機受入と配布候補

固定SHAの通常Releaseで、実際の選択→コピー→履歴再利用、取消、別コピー、終了、常駐負荷を確認します。通常版とDemo、最低OSとアーキテクチャ、署名・DMG・更新の影響を確認し、手順・制約・結果を文書へ反映します。

重大な既存不具合が再現した場合は、OCRの磨き込みより先にその修正を行います。公開権限がなければ検証候補で止め、無断で公開Releaseや導入先を変更しません。

### 作業運用

テストは最小の関連範囲から始め、最終候補で全体を実行します。一行ごとの全テスト、同じ失敗の無目的な反復、テスト数・カバレッジ率のノルマを作りません。

変更する理由があるファイルだけを触り、Managerが大きいという理由だけの分割、全依存更新、汎用DI・ジョブ・イベント基盤の追加は避けます。

環境がなく実施できない項目は、必要な本人操作と最小の試験手順を示します。未実施をPASSとせず、環境待ちに関係しない実装・検証は完了させます。

## 18. ビルド・配布・ドキュメント

`project.yml`を構成の基準として、ScreenCaptureKit・Visionと必要なOSフレームワークを追加します。既存のXcodeGenとビルド入口を使い、生成プロジェクトとの乖離を作りません。[R1]

外部のOCRモデル、Python、Node、ローカルHTTPサーバーを通常アプリの依存へ追加しません。OSフレームワークと必要なアプリコードだけで利用できる状態を目指します。
