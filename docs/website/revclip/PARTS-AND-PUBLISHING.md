# 掲載部品とCMS移行の編集設計

このファイルは編集者向けです。2026-09-17に本設計を基にCMS登録まで実施しました。[登録記録](CMS-REGISTRATION.md)に結果を記載しています。製品の利用ガイド本文には掲載しません。ローカルMarkdownの作成後、CMS登録と承認済みのサイトデプロイを実施しました。各工程の証拠と未確認範囲は登録記録を参照してください。

## 確認した既存サイト構造

サイトリポジトリ `revcn` の以下を参照しました。

- `src/lib/revcn/docs-data.ts`: DocsのCMS取得、文書パス・ナビゲーション・本文ブロック。
- `src/components/revcn/website/docs/docs-article-body.tsx`: CMSのブロックを優先する記事本文。
- `src/lib/revcn/content-blocks/registry.tsx`: 登録済みブロックとrenderer。
- `src/lib/revcn/content-blocks/schema.ts`: ブロックの型・必須項目。
- `src/components/revcn/content-blocks/content-code.tsx`: コード表示とコピー操作。

これらは既存部品の対応表の根拠です。ローカルMarkdownを置いただけではCMS本文へ変換されません。サイトの実装・CMSの現行状態は登録時に再確認します。

## Markdownから既存部品への対応

| 原稿での表現 | 既存blockType | 使う箇所 | 移行時の注意 |
| --- | --- | --- | --- |
| 見出し・段落・箇条書き・番号手順 | `richText` | 基本説明、インストール、操作手順 | Markdownの見出しを保ち、目次とアンカーを検証する |
| 引用形式の注意・補足 | `callout` | 権限、CLI制限、削除の範囲、通信 | `tone`は`info`・`warning`・`success`・`danger`。本文にない保証を足さない |
| fenced code block | `code` | CLI、エージェントへ渡すプロンプト | `code`・`language`を設定。コピー後にプレースホルダーを置き換える箇所を説明する |
| Markdownテーブル | `dataTable` | 対応形式、設定、削除、コマンド比較 | `columns`と`rows`へ変換し、長文セル・狭い幅で確認する |
| 症状ごとの小見出しと回答 | `accordion` | FAQ、トラブル対処の補足 | 必須の注意や操作の前提は折りたたまない |
| 関連ページへの短い案内 | `cta` | インストール、次の章、不具合報告の案内 | 内部パスまたはHTTPS。サイト側の最終パス確定後にリンクを置換する |

### 図・画像・動画

既存の`flowDiagram`は専用schemaに従うデータが必要です。原稿にMermaidを記載しても、そのままCMSで描画されるとは扱いません。コピー→保存→選択→復元を図にする場合も、同じ情報を文章で読めるようにします。

`carousel`は説明に必要な実画像と代替テキストが揃った場合だけ利用します。ユーザーの実履歴・個人情報・APIキーが映る画像は掲載しません。空の画像枠や架空のスクリーンショットを原稿へ入れません。

既存`video`はYouTubeの動画IDを要求します。任意のローカル動画パスを指定して動作する前提にしません。今回、動画を新規作成・公開する必要はありません。

未測定の性能をチャート化しません。専用TabsやStepsブロックが存在する前提も置かず、通常の見出し・番号手順で完成させます。

## 原稿の編集コメント

`<!-- block: callout tone=warning -->`などは、部品化候補を編集者へ伝えるコメントです。自動変換できるDSLとしては定義しません。本文はコメントを除いても成立させます。

各章末尾の出典コメントは、確認元のファイルとsymbol・節を記載します。読者向け本文の内部構造説明を増やすためではなく、仕様更新時の照合に使用します。

## CMSに移す段階の確認

1. 入口ページ・原稿12章と導線を読み、実在する操作・CLI・安全境界を照合する。
2. CMSの既存Revclipページ・slug・親子関係を読み取り、重複登録を避ける。
3. `title`・`summary`・`productArea`・`docVersion`・`navOrder`・`parent`を実schemaに合わせる。原稿の`description`はサイト側の`summary`候補であり、無変換の投入を前提にしない。
4. 通常本文をCMSのLexicalへ、必要箇所を既存ブロックへ変換する。ローカルMarkdownをフォールバックJSONへ直接埋め込まない。
5. 登録前後の文書ID・パス・本文を照合し、内部リンク・目次・コードコピーを確認する。
6. CMS保存とサイトのビルド／配信は別工程として報告する。デプロイはユーザーの明示的な承認に基づいて実施する。

## 確認状態の表現

「原稿完成」「CMS登録済み」「プレビュー確認済み」「公開済み」を区別します。本文の完成から、CMS保存・公開・実画面の正常表示を推定しません。
