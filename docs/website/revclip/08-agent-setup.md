# エージェントにRevclipスキルを登録する

この手順では、Revclipに同梱された`revclip`スキルを、Mac上で検出された対応エージェントへ登録します。初回導入とアプリ更新後のスキル更新には、エージェントで実行するセットアップ用プロンプトを使います。導入は手動です。

<!-- block: callout tone=warning -->
> **確認状況:** 対象のRevclip 0.1.9（build 42）は、実機での受け入れ確認が完了していません。このページはソースで照合した手順を説明するもので、すべてのエージェント環境で読み込みを確認したという意味ではありません。

## 対応先の検出は既定の設定場所を使う

インストーラーは、次の設定場所が存在するかを確認します。フォルダが見つかっても、その製品が今インストール済み、または起動中だとは限りません。見つからない場所はスキップします。

<!-- block: dataTable -->
| エージェント | 既定の検出先 | 補足 |
| --- | --- | --- |
| Codex | `~/.codex` | `CODEX_HOME`が設定されている場合はその場所を検出し、`skills`へ登録します。設定がない場合の登録先は共有スキル領域の`~/.agents/skills`です。 |
| Claude Code | `~/.claude` | `CLAUDE_CONFIG_DIR`が設定されている場合は、その場所を使います。 |
| Cursor | `~/.cursor` | 検出先の下にある`skills`へ登録します。 |
| Antigravity 2.0 | `~/.gemini/config` | Antigravity IDEとは別の検出先です。 |
| Antigravity IDE | `~/.gemini/antigravity` | Antigravity 2.0とは別の検出先です。 |
| Gemini CLI | `~/.gemini` | `GEMINI_CLI_HOME`が設定されている場合は、その場所の`.gemini`を検出先として使います。 |
| Grok Build | `~/.grok` | `GROK_HOME`が設定されている場合は、その場所を使います。 |
| Kimi Code | `~/.kimi-code` | `KIMI_CODE_HOME`が設定されている場合は、その場所を使います。 |
| Kimi CLI（Python版） | `~/.kimi` | 旧CLI向けの検出先です。 |
| Hermes Agent | `~/.hermes` | `HERMES_HOME`が設定されている場合は、その場所を使います。 |
| DeepSeek Harness | `~/.dsh` | `DSH_HOME`が設定されている場合は、その場所を使います。実験的対応です。 |

Antigravity CLIは検出結果に表示される場合がありますが、同梱スキル一式の導入先としては未対応です。公式資料で確認できる形式と同梱ファイルの形式が一致するか確認できていないため、インストールされません。DeepSeekのモデル利用だけでは対象になりません。DeepSeek Harnessは別のエージェントで、ファイルシステム型のスキル提供機能が使える状態かどうかまでは判定しません。

環境変数による設定場所の指定は、既定の検出先を置き換えます。指定先が存在しない場合はスキップします。既定の場所へ戻って検索しません。検出は決められた場所に限られます。ホーム全体を再帰的に検索せず、エージェントの設定ファイルや認証情報ファイルも開きません。

## プロンプトから導入し、結果を確認する

1. Revclipの「設定」から「エージェント設定」を開きます。画面を開くとインストール状態を確認します。読み取り専用です。「スキルの更新を確認」も状態を確かめるだけで、導入や更新は始めません。
2. 画面の「プロンプトをコピー」を押します。一般クリップボードの前の内容は読みません。いったん空にして、表示中のセットアップ用プロンプトを書き込みます。別の内容を残したい場合は、先に保存してください。
3. コピーしたプロンプトをCodexまたはClaude Codeへ貼り付けます。そのまま実行してください。現在のアプリに同梱されたCLIの場所と対象アプリ名はプロンプトに組み込まれているため、利用者がアプリ名やCLIのパスを書き換える必要はありません。コマンドは`inspect`、`install`、最後の`inspect`の順です。
4. 導入先、スキップ、競合を確認します。競合が出た製品では止めてください。内容を手作業で上書き・削除して続けないでください。
5. Codexでは新しいセッションを開始します。ほかの製品は、セットアップ結果に示された再読み込み方法に従ってください。

追加の指示を添える場合は、次の例を使えます。セットアップ用プロンプトには実際のCLIパスと対象アプリ名が入るので、アプリ画面からコピーしたものを使ってください。

<!-- block: code language=text -->
```text
画面からコピーしたRevclipのセットアップ用プロンプトをそのまま実行してください。inspect、install、inspectの結果を確認し、導入先・スキップ・競合を報告してください。エラーや競合があれば停止し、強制実行・上書き・削除で回避しないでください。
```

## 導入済みスキルはアプリ更新後に手動で更新する

アプリを更新しても、登録済みスキルは自動では上書きされません。「エージェント設定」を開くか「スキルの更新を確認」を押して更新有無を調べます。更新が表示されたら、セットアップ用プロンプトをもう一度実行してください。更新は手動です。

配布アプリにはネイティブCLIとスキル一式が含まれており、導入にPythonやソースリポジトリは必要ありません。ターミナルで実行する場合は、`APP`を対象アプリの場所に置き換えてから、同じ3コマンドを実行します。以下の値は相対パスの記入例です。

<!-- block: code language=sh -->
```sh
APP='path/to/Revclip.app'
"$APP/Contents/Helpers/revclip" agent inspect --app Revclip
"$APP/Contents/Helpers/revclip" agent install --app Revclip
"$APP/Contents/Helpers/revclip" agent inspect --app Revclip
```

`agent inspect`は読み取り専用です。`agent install`は検出された対応先の`revclip`スキル用フォルダへ、スキル本文、ネイティブCLI、エージェント向けメタデータをコピーします。通常版では`--app Revclip`を使います。Demo版を使う場合は、`APP`をDemo版アプリの場所にし、3コマンドの`--app Revclip`をすべて`--app revclip-demo`に置き換えてください。これらのコマンドはRevclipアプリの起動中でなくても実行できます。

## 結果の状態を見て、読み込みまで確認する

CLIのJSON結果では、`state`がスキルの配置状態、`action`が今回の操作結果を表します。現在のネイティブCLIが返す主な値は次のとおりです。

<!-- block: dataTable -->
| 結果 | 意味と次の操作 |
| --- | --- |
| `state: current` | 管理情報とファイル内容が同梱版に一致しています。`update_available: false`なら追加の更新はありません。 |
| `state: managed` | 管理情報を確認できた導入済みコピーです。同梱版と内容が異なる場合は`update_available: true`となり、セットアップ用プロンプトで更新できます。 |
| `action: installed` / `updated` / `unchanged` | 新規導入、管理対象の更新、または変更なしで完了したことを表します。 |
| `state: missing` | 管理対象のスキルがありません。検出先自体が存在しないときは、その製品はスキップされます。 |
| `state: conflict` | 未管理のコピー、編集済みファイル、予期しない内容などがあり、変更を止めています。既存ファイルは上書きされません。 |
| `state: unsupported` | 同梱形式での導入に対応していません。Antigravity CLIが該当します。 |

複数のエージェントへ導入する処理は個別に行われます。ある製品で失敗しても、別の製品で完了した導入が取り消されるとは限りません。最後の`inspect`で製品ごとの状態を確認してください。`current`はファイルが同梱版と一致する状態です。エージェントが読み込んだ印ではありません。結果に示された再読み込みを行ったあと、エージェントへRevclipのテンプレート管理を依頼して確認します。

## 競合や読み込み失敗が起きたとき

結果に表示された状態に応じて、以下の手順で確認します。

### 対応エージェントが検出されない

設定場所を標準以外へ移している場合、インストーラーが使う環境変数の値が起動中のRevclipへ渡っているか確認します。設定値があると既定の検出先より優先され、指定先が存在しない場合はスキップされます。インストーラーは別の場所を探し回りません。

### `conflict`またはロックのエラーが出る

インストーラーが更新するのは、管理対象と確認でき、内容が記録と一致するスキルです。未管理の`revclip`フォルダや編集済みスキルは競合として報告し、そのまま残します。強制オプションはありません。同時にセットアップを複数回実行している場合は、先の処理が終わるまで待ってください。中断した処理のロックや一時フォルダが残っても、自動では削除しません。原因が分からないときは手作業で削除せず、結果を添えて[トラブルシューティング](11-troubleshooting.md)を確認してください。

### 導入済みなのにエージェントが使わない

結果に示された再読み込みを行い、新しいセッションで試してください。カスタムのスキル検索先やエージェント側の機能設定は、インストーラーの検査対象ではありません。DeepSeek Harnessでは、既定の設定場所が見つかってもファイルシステム型のスキル提供機能が有効とは限りません。

<!-- block: callout tone=warning -->
> **エージェントの権限:** Revclip CLIはコピー履歴一覧・履歴本文・現在のクリップボードを返すコマンドを提供しません。ただし、これはOS権限を持つエージェントを隔離する機能ではありません。同じOSユーザーとして動くエージェントは、別のOS機能を通じてクリップボードや画面などへアクセスできる場合があります。保存データの暗号化も、OS権限からの完全な隔離を意味しません。

## エージェントへテンプレート管理を依頼する

スキルの再読み込み後は、対象アプリと変更内容を指定します。次の例は通常版向けです。自分のテンプレート名・本文に置き換えて使ってください。

### 作成する

フォルダと本文を指定して、新しいテンプレートを作ります。

```text
Revclipスキルを使い、通常版Revclipに「メール」フォルダがあるか確認してください。
なければ作成し、その中にタイトル「受領の返信」、本文「ご連絡ありがとうございます。内容を確認してご返信します。」のテンプレートを作成してください。
同名の項目がすでにある場合は追加せず知らせてください。保存後にIDと保存内容を確認してください。
```

### 編集する

対象を特定して、本文だけを変更します。

```text
通常版Revclipの「メール」フォルダにある「受領の返信」を探し、本文を「ご連絡ありがとうございます。確認後、担当者よりご返信します。」に変更してください。
同名が複数ある場合は対象を確認してください。タイトルと配置先は維持し、保存後の内容を確認してください。
```

### 削除する

指定したテンプレート1件を削除します。

```text
通常版Revclipの「メール」フォルダにある「受領の返信」を削除してください。
同名が複数ある場合は対象を確認してください。他のテンプレートとフォルダは残し、対象IDが一覧から消えたことを確認してください。
```

これらはテンプレートの操作です。エージェント用CLIはコピー履歴や現在のクリップボードを読めません。作成・編集後はRevclipのテンプレートメニューで内容と貼り付け結果を確認できます。
