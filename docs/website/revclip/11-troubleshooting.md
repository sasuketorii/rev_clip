# トラブルシューティング

症状に合わせて、アプリの起動状態、保存タイプ、macOSの許可、貼り付け先を順に確認できます。切り分けには、共有しても問題のない短いテスト文を使ってください。履歴の消去、設定の初期化、Panic、アプリ内データの削除は、通常の確認手順に含まれません。

<!-- block: callout tone=warning -->
> **v0.1.9（build 42）の確認範囲**：公開版のCIと配布物は確認されていますが、実機でのメニュー再描画、実際の貼り付け、連続コピー、Finder画像プレビュー、Sparkle経由の更新操作は受け入れ確認が完了していません。以下の手順は原因の切り分けに役立ちますが、すべてのMacやアプリでの動作を保証するものではありません。

## まず確認すること

1. Revclipのメニューから「設定 → アップデート」を開き、表示されるバージョンとbuildを確認します。公開版は **0.1.9（42）** です。
2. 機密情報を含まない短い文字列（例：`Revclip 動作確認`）を、普段のコピー操作でコピーします。
3. 少し待ってから **⌘⇧V** またはメニューバーのRevclipアイコンでメニューを開きます。すでにメニューを開いていた場合は、一度閉じてから開き直します。

**確認できる状態：** 保存対象の種類に合い、除外されていないコピーであれば、履歴メニューにテスト文が表示されます。表示されない場合は、次の症状別手順へ進んでください。

## アプリが起動しない、またはメニューが開かない

1. DMGから導入した場合は、アプリを「アプリケーション」フォルダへコピーしてから、そのアプリを起動します。ダウンロードしたDMG内のアプリを開いたまま使っていないか確認します。
2. メニューバーにアイコンがない場合は、別の入口から **⌘⇧V** を試します。アイコン表示を無効にしていると、メニューバーには表示されません。
3. **⌘⇧V** が開かない場合は「設定 → ショートカット」で現在の割り当てを確認し、登録済みのショートカットを使います。必要ならメニューバーのアイコンから設定を開きます。

**確認できる状態：** メニューバーのアイコン、または現在設定されているショートカットからRevclipのメニューが開きます。macOSが起動を止めた場合は、画面に表示された案内と公式配布元の手順を確認してください。

## コピーが遅れて表示される、履歴に見つからない

1. 「設定 → 除外アプリ」を開き、コピーに使ったアプリが記録対象から除外されていないか確認します。除外設定は、コピーが観測された時点の前面アプリを基準に判定します。記録したいアプリだけを必要に応じて変更してください。
2. 「設定 → 種類（保存タイプ）」で、コピー元が提供する種類が有効か確認します。文字なら「プレーンテキスト」、画像データなら「画像 (TIFF)」、Finderで選んだファイルなら「ファイル名」など、対象に合う種類を確認します。
3. コピー直後にメニューを開いて古い一覧が見えたら、少し待って閉じ、もう一度開きます。v0.1.9では、保存完了後にメニューバーの一覧をその場で更新する場合がありますが、項目を選択中、またはサブメニューを開いている間は更新を保留します。
4. コピー時にmacOSのクリップボードアクセス許可が表示された場合は、次の「macOSが許可を求める」を確認します。

Revclipはクリップボードを既定で500ms間隔に観測します。これは履歴への表示時間の上限ではありません。観測より前に別のコピーで上書きされた内容を、後から復元する保証はありません。コピー元が遅れて提供する形式や、アプリ固有の形式も、すべてのケースで保存・復元できるとは限りません。

**確認できる状態：** 許可された保存タイプのコピーが、観測・保存された後に履歴へ表示されます。テスト文も表示されなければ、使ったコピー元アプリ、形式（文字・画像・ファイルなど）、メニューを開いた入口を控えてください。コピー内容そのものは報告へ含めないでください。

## 選んでも貼り付けない、または貼り付け先が変わる

1. 目的の入力欄をクリックしてフォーカスを合わせてから、Revclipのメニューを開きます。
2. 「設定 → 一般 → ペーストコマンド」がオフなら、項目を選んだ後に貼り付け先で **⌘V** を押します。項目の選択でクリップボードへの復元は行われますが、自動でキーを送信しません。
3. ペーストコマンドがオンで自動貼り付けできない場合は、「macOSが許可を求める」のアクセシビリティ手順を確認します。
4. メニューを開いた後に別のアプリや入力欄へ移動した場合は、意図した貼り付け先へ戻ってメニューを開き直し、項目を選び直します。

Revclipは選択までの間に前面アプリ、入力フォーカス、クリップボードの状態が変わると、自動のキー送信を取り消すことがあります。別のアプリや入力欄へ誤送信しないための確認です。

**確認できる状態：** ペーストコマンドがオフなら、選択した内容を貼り付け先で **⌘V** して利用できます。オンなら、許可された状態で、開いたときの貼り付け先が維持されている場合に自動貼り付けが行われます。

## macOSが許可を求める

クリップボードへのアクセス許可とアクセシビリティ許可は用途が異なります。

| 許可 | 用途 | 確認方法 |
| --- | --- | --- |
| クリップボードアクセス | コピー内容を履歴へ取り込む | macOSが許可を求めたら、内容の取り込みを望む場合に許可します。拒否済みの場合は、Revclipの案内からシステム設定を開き、クリップボードの許可を確認します。 |
| アクセシビリティ | 自動貼り付けのために ⌘V のキー入力を送る | 「システム設定 → プライバシーとセキュリティ → アクセシビリティ」でRevclipを許可します。 |

macOSのバージョンや設定によっては、クリップボードアクセスに明示的な許可が必要になる場合があります。許可画面や設定項目の名前はmacOSのバージョンで異なることがあります。クリップボードアクセスを許可しない場合、コピーを履歴へ取り込めません。アクセシビリティを許可しない場合も、項目の復元後に貼り付け先で **⌘V** を使う方法があります。

**確認できる状態：** クリップボードアクセスを許可し、保存タイプなどの条件も満たしたコピーを取り込める状態になります。アクセシビリティを許可すると自動貼り付けを使えます。片方の許可で、もう片方の用途が有効になるわけではありません。

## Finderでコピーした画像のプレビューが違う、または出ない

Finderで画像ファイルを **⌘C** した場合は、通常、画像のピクセルだけでなくファイルへの参照がコピーされます。Revclipはローカルで読み込める画像ファイルから内容のプレビューを作成し、貼り付け時にはファイル参照を含む元の形式を保ちます。

1. ファイルへの参照を履歴に残す場合は、「設定 → 種類（保存タイプ）」で「ファイル名」が有効か確認します。
2. 画像のピクセルをコピーした場合は、「画像 (TIFF)」が有効か確認します。ファイル参照と画像データは別のコピー形式です。
3. プレビューが出ない場合は、コピー元のファイルがローカルの通常ファイルで、iCloudなどからのダウンロードも完了しているか確認します。Revclipは複数ファイルをコピーしたとき、プレビューには先頭のファイルを使います。
4. Finderが提供するアイコン画像が表示されても、貼り付け形式が画像だけに変わったとは限りません。履歴項目を選んで、目的の場所へファイルとして貼り付けられるか確認します。

**確認できる状態：** 読み込み可能な画像ファイルなら、ホバー時にファイルの内容をプレビューできます。プレビューを表示できない場合も、履歴項目のファイル参照自体が保存されていることがあります。v0.1.9の実機Finderプレビューは受け入れ確認が未完了のため、表示の問題が続く場合は手順を記録してください。

## ホバープレビューが出ない、またはURLカードにならない

1. サブメニューを開く親行ではなく、内容のある履歴項目へポインタを合わせます。画像のプレビューは、保存された画像データから作られます。画像を読み込めないときは小さなサムネイルへ戻る場合があります。
2. SVGのプレビューは、対応するSVGコード単体が対象です。外部参照、スクリプト、埋め込み画像、CSS、アニメーションなどを含む場合は、通常の文章プレビューへ戻ります。
3. リンクカードを確認する場合は、コピー内容全体がURLであることを確かめます。文章の中にURLが含まれているだけの場合は文章プレビューです。
4. URL単体でも画像やファビコンが出ない場合は、ネットワーク接続と接続先サイトの提供内容を確認します。ログインが必要なサイトや画像を提供しないサイトでは、カード画像やファビコンが出ないことがあります。

**確認できる状態：** 対応形式ならホバー時にプレビューが表示されます。プレビューの有無にかかわらず、保存された項目はメニューから選択できます。URLの内容にアクセスしてプレビューを取得する場合はネットワークを使います。

## CLIでエラーになる、またはアプリに接続できない

CLIはRevclipアプリに同梱されているネイティブ実行ファイルです。Pythonやリポジトリの作業環境は必要ありません。まず、起動中のアプリと同じアプリの場所を `APP` に指定してください。アプリ連携を確かめるコマンドは、対象アプリを起動した状態で実行します。

```sh
APP='path/to/Revclip.app'
"$APP/Contents/Helpers/revclip" --help
"$APP/Contents/Helpers/revclip" --app Revclip settings-schema
```

`settings-schema` は利用可能な設定名・型・範囲を表示します。設定値そのものを読むコマンドではありません。テンプレート・設定・バグ報告のCLI操作には、対象アプリの起動が必要です。接続エラーが出た場合は、Revclipを起動し、通常版なら `--app Revclip`、Demo版なら `--app revclip-demo` を指定しているか確認します。CLIは対象アプリを自動起動しません。

エージェントスキルの状態だけを確認する場合は、アプリを起動せずに次の読み取り専用コマンドを使えます。

```sh
APP='path/to/Revclip.app'
"$APP/Contents/Helpers/revclip" agent inspect --app Revclip
```

CLIが扱うのはテンプレート、許可された設定、同意付きのバグ報告です。コピー履歴の一覧・本文や現在のクリップボードを読むコマンドはありません。履歴の確認にCLIやファイルアクセスの回避策を使わないでください。このCLIの制限と保存時の暗号化は、同じOSユーザーの広い権限から履歴を完全に隔離するものではありません。

**確認できる状態：** `--help` はCLIの使い方を表示し、起動中の対象アプリに対する `settings-schema` はサポートされる設定のschemaを返します。`agent inspect` は検出した対応エージェントごとの導入状態を返します。

## エージェントにRevclipスキルが表示されない、更新されない

1. Revclipの「設定 → エージェント設定」を開き、「スキルの更新を確認」を押します。この確認は導入状態を調べるだけで、スキルをインストール・更新しません。
2. 更新が表示されたら、セットアップ用プロンプトをコピーして、対象のエージェントで手動実行します。結果にある導入先、スキップ、競合を確認し、必要なら同じ画面で再確認します。
3. `conflict` やローカル変更の案内が出た場合は、手動編集した内容を保持してください。インストーラに上書きを強制したり、既存スキルのフォルダを削除したりしません。
4. 導入済みでもエージェントが認識しない場合は、対象エージェントの案内に従って再読み込みするか、新しいセッションを開始します。手順は[エージェント設定](08-agent-setup.md)で確認できます。

Revclipのアップデートだけでは、導入済みスキルは自動更新されません。`installed` は管理情報とファイル内容の一致を示し、エージェントがそのスキルを読み込んだことまでは示しません。導入対象の設定領域が見つからない場合、Revclipはその領域を勝手に作成せず、ホーム全体を検索しません。

**確認できる状態：** 再確認の結果に導入先の状態が表示され、セットアップ用プロンプトを実行した場合は、管理対象で変更されていないスキルだけがインストールまたは更新されます。最後に対象エージェントを再読み込みして認識を確認します。

## 表示されるバージョンが違う、アップデート後も変わらない

1. 起動中のRevclipで「設定 → アップデート」を開き、バージョンとbuildを確認します。公開版の表示は `0.1.9 (42)` です。
2. 通常版の場合は「今すぐ確認」を使い、macOSやSparkleの画面が表示されたら、その内容を確認して画面上で操作します。更新後にRevclipを開き直し、表示される版をもう一度確認します。
3. Demo版を使っている場合は、通常版の更新フィードからは更新されません。Demo版向けに案内された配布手順を使います。
4. CLIも併用している場合は、起動中のアプリと同じ `.app` に含まれる `Contents/Helpers/revclip` を使い、CLIの `--app` もそのアプリに合わせます。

**確認できる状態：** 起動中のアプリが設定画面に `0.1.9 (42)` と表示されます。公開フィードや配布物の確認と、実機でSparkleの更新画面を完了する操作は別です。v0.1.9のSparkle更新操作は実機受け入れ確認が未完了のため、画面に出た受付表示だけで更新完了とは判断しないでください。

## 解決しないとき

次の情報を控えると、問題を再現しやすくなります。

| 控える情報 | 例 |
| --- | --- |
| Revclipの版 | 設定画面のバージョンとbuild |
| macOSの版 | macOSのバージョン |
| 操作手順 | コピー元の種類、メニューを開いた入口、選択後に起きたこと |
| 許可・設定 | コピーアクセスやアクセシビリティの許可状態、ペーストコマンドの設定 |

コピー内容、履歴本文、テンプレート本文、認証情報、秘密を含むURL、個人情報が映ったスクリーンショットやログを報告へ添付しないでください。バグ報告を送る場合は、送信内容と同意条件を[アップデートとフィードバック](12-updates-and-feedback.md)で確認してください。
